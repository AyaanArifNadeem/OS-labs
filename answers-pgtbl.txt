1)The print_pgtbl output maps out the user process exactly as xv6 builds it from the ground up. Starting at virtual addresses 0x0 and 0x1000, the permissions (0x5B and 0x1B) include the Execute and User flags, meaning these pages hold the actual compiled code (text segment) of the program. Right above that at 0x2000 (0x17), the Execute flag is swapped for the Write flag, creating the data segment where the program's global variables live. Address 0x3000 (0x7) is the clever part: it lacks the User bit entirely, acting as an invisible "guard page" that will safely crash the program if the stack grows too deep and tries to overwrite the data below it. Sitting directly on top of that guard at 0x4000 (0xD7) is the user stack itself, which is readable, writable, and user-accessible. Finally, the two pages sitting at the absolute highest virtual addresses (0x3FFFFFE000 and 0x3FFFFFF000) completely lack the User bit because they belong strictly to the kernel. The writable one (0xC7) is the trapframe used to securely save CPU registers during system calls, and the executable one (0x4B) is the trampoline page containing the secure code needed to bounce the CPU between user and kernel mode. 


2)The leaf pages in your vmprint output represent the exact same memory segments decoded in the earlier print_pgtbl exercise, just visualized hierarchically. Starting at the bottom of memory, virtual addresses 0x0 and 0x1000 (RXU) hold the program's compiled code, allowing the user to read and execute instructions without being able to accidentally modify them. Right above that, 0x2000 (RWU) is the data segment for global variables, which the user process can read and write but not run as executable code. Address 0x3000 (RW) acts as a protective guard page; it intentionally lacks a User (U) bit so that if the readable and writable user stack directly above it at 0x4000 (RWU) overflows, the hardware instantly triggers a fault before the data segment gets corrupted. Finally, the highest memory addresses are strictly reserved for the kernel and lack User bits: the trapframe at 0x3fffffe000 (RW) securely stores CPU registers during system calls, and the trampoline at 0x3ffffff000 (RX) contains the privileged instructions needed to safely transition the processor from user mode into kernel mode.
